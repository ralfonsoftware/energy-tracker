## What Went Well

- **`bmad-correct-course` handled a live bug cleanly and fast.** From root-cause investigation to two inserted stories (11.13, then the FR-51 amendment for 11.14) to shipped fix — same day, twice — without derailing the rest of the epic's planned batch. Ralf specifically called this out as a highlight.
- **The FR-51 amendment showed process discipline, not just a hotfix.** Story 11.14 didn't just patch on top of 11.13's write-time dedup guard — it recognized the underlying FR itself needed amending once the unlimited-retention tradeoff's practical consequence (an ever-growing default view, no dismiss feature yet) became concrete.
- **Story 11.9's UX design gate held as a genuine hard gate.** The epic text explicitly withheld the visual spec ("cannot proceed until Ralf and Sally decide"), and no implementation code was written until a real mockup was reviewed and approved. Sally's own first proposal (a mirrored hatch pattern) was revised after Ralf found it hard to distinguish from the existing reset hatch at 30-day density — the gate produced a better outcome, not just a checkbox.
- **Adversarial code review kept finding real, non-cosmetic bugs** — continuing the pattern from Epic 10. Story 11.2's entire point (a DB-level lock closing the insights-redelivery race) had a silent no-op in its first pass: the claim transition reassigned the same enum value, so EF's change tracker never marked it dirty and a redelivered invocation sailed through undetected. Story 11.8 had an analogous first-pass gap — whole-set replace/clear instead of per-key add/remove, directly contradicting the story's own "a second `mutate()` call is structurally impossible" claim. Both catches were about *state-transition* logic specifically, not business logic — a pattern worth remembering for future first-pass review focus.
- **Knowledge transfer between stories worked.** Each story's "Previous Story Intelligence" section propagated concrete lessons forward — the InMemory-provider test-double technique (Story 11.2's `RowVersionSimulatingDbContext` → Story 11.3's `UniqueConstraintConflictDbContext`), exact-count assertions over loose ones, `dotnet test` invoked from `api.Tests/` since no root `.sln` exists, and more.

## Challenges & Patterns

- **Five-plus stories found the epic's own AC text was wrong or stale before any code was written.** Story 11.3 caught a literal reading of the epic ("a filtered unique index on `PlugId`") that would have made the constraint globally unique across all flats, directly contradicting an already-passing, intentional cross-flat test. Story 11.12 caught an AC describing a SQL-Server-only DDL failure mode (multiple cascade paths) that SQLite structurally cannot reproduce — a test built to the literal words would have passed trivially and proven nothing. Story 11.10 discovered its entire premise (a test-coverage gap) had already been closed three weeks *before* the epic was even scoped. **Resolution reached in this retro:** this is an accepted division of labor, not a defect — epics should nail scope, and `create-story`'s deeper verification pass is where AC-level correctness gets finalized. Ralf confirmed this explicitly; no process change needed.
- **EF Core's `InMemory` test provider limitations recurred across three stories.** Stories 11.2, 11.3, and 11.12 each needed a "test-double `DbContext` subclass that throws on `SaveChangesAsync`" workaround to simulate a DB-level failure `InMemory` can't produce natively (RowVersion bump, unique-index enforcement). Story 11.12 (the SQLite integration tier) is the actual structural fix for this class of problem, and it landed within the same epic — good sequencing, if not originally planned that way.
- **A migration assumption broke against real data.** Story 11.3's migration assumed a fresh schema with no production data; the first `dotnet ef database update` attempt against the real dev DB failed because pre-existing rows collapsed onto a shared default `FlatId`. Required a hand-added SQL backfill mid-story. Not a process failure, but a reminder that "fresh schema" isn't a safe assumption to write into Dev Notes without checking first.
- **Two of Epic 10's five action items never closed.** #2 (Winston: a durable architecture-review checklist entry for "check all nullable-FK cascade paths on an entity together") and #5 (Murat: tighten test-naming-vs-assertion discipline during `dev-story` itself) both stayed as informal awareness rather than becoming durable artifacts or process changes. Carried forward into this retro's action items.
- **`deferred-work.md` hygiene continues to lag.** The file had grown to 75 review sections with only 7 marked closed before this retro (up from ~68 open items at Epic 10's close). Several stories in this epic (11.6, 11.9, 11.10, 11.11) each did their own small hygiene pass closing their own directly-relevant stale entries — good instinct, but the file as a whole isn't getting a systemic pass. During this retro, 4 additional stale entries were found and closed (the `ResolveTariff` tie-break, closed by Story 11.1 but never struck through in 3 separate review sections; `PeriodSelector.tsx`'s keyboard-nav/`aria-expanded` gap, closed by Story 11.7 but never struck through).
