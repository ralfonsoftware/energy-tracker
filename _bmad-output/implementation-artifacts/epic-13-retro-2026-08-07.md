- Test suite: 568 → 578 backend, 515 → 518 frontend, zero regressions across all three stories

- Root cause fully closed, not patched: `UpdateFlatStructureFunction.cs`'s whole-flat-replace endpoint — the actual mechanism behind the confirmed data-loss bug — is deleted entirely. Devices got their own atomic save endpoint (13.1), then rooms/power-points got theirs (13.2), each with per-entity `RowVersion` concurrency checks. 13.3 added defense-in-depth DB validation/cleanup scripts and confirmed a clean production baseline (zero anomalies).

## What Went Well

- **The whole-flat-replace endpoint was deleted, not deprecated-and-left.** Once nothing needed `UpdateFlatStructureFunction.cs`/`UpdateFlatStructureValidator.cs`/the old DTOs, they were removed entirely rather than left as unused, still-exploitable dead code. Third clean instance of this project's "delete rather than leave a shim" convention (after `TariffResolver` in the Epic 9 retro).
- **Consistent concurrency pattern across two stories.** Story 13.1 established the per-entity `RowVersion` check pattern at the Device level; Story 13.2 reused it verbatim at the Room level, deliberately choosing not to add a redundant per-PowerPoint check since EF's automatic optimistic-concurrency-on-save already covers nested entities. No reinvention, no drift.
- **13.3 shipped the safety net even though it found nothing.** The validation script confirmed zero anomalies in production (matching the epic-scoping baseline from 2026-08-02) — the story still delivered the cleanup script ready-to-use rather than treating the clean result as a reason to skip it.
- **Adversarial code review kept catching real bugs before merge.** Story 13.2's review caught `isRoomDirty` permanently flagging non-first rooms as dirty (a `sortOrder`-comparison bug that would have shipped as a persistent, unexplained UI annoyance) and a 404-vs-409 error-handling bug that would have left "phantom" undeletable rooms in the UI after a room was deleted elsewhere. Story 13.1's review caught 8 issues including a duplicate-submit risk and a validator bypass. Continues the pattern the Epic 12 retro already called out.

## Challenges & Patterns

- **Two Epic 12-retro commitments were dropped — genuinely forgotten, per Ralf.** That retro's Action Items #2 and #3 explicitly stated the FK-cascade-path architecture-review checklist (Winston) and test-naming-vs-assertion discipline (Murat) would become real Epic 13 stories. Neither appears anywhere in Epic 13's planning or story files. These items originated in the Epic 10 retro and are now **4 epics stale** with zero artifact ever produced. Root cause identified this retro: retro action items live only as prose in a markdown file that nobody reopens during the next epic's authoring — there is no durable, checkable mechanism forcing them back into view.
- **`deferred-work.md` wasn't touched by this epic, despite generating real deferred findings.** The file sat at 81 open / 3 closed at the Epic 12 retro; it's now 83 open. But zero of those new entries came from Stories 13.1 or 13.2, even though those stories' code reviews produced 8 combined `[Review][Defer]` findings. Those findings exist only inside the story files' "Review Findings" sections — invisible to the file whose entire purpose is tracking exactly this kind of item. This confirms the hygiene gap flagged in the last two retros is actively growing, not just stagnant.
- **Story 13.2's "Gap found during story creation" section recurred** despite the Epic 12 retro's Action Item #1 (verify epic ACs against current code before story-creation, to catch exactly this class of gap earlier). Whether that verification step was actually applied to Epic 13's authoring could not be confirmed this retro — Winston had no clear record either way. An action item with no artifact trail is itself a symptom of the same underlying problem as the two dropped commitments above.
